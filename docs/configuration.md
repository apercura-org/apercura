# Configuration

Every setting is an environment variable, read from a single `.env` file at
the repository root (the web app, the import and the migrations share it) or
from the host's environment. The web app validates its variables at start-up
with the schema in `apps/web/src/env.ts`; `SKIP_ENV_VALIDATION=1` skips that
check (CI lint jobs, Docker image builds).

`bun run keys:generate` prints fresh values for every secret below that is
marked _generate_.

## Scheduled jobs (`bun run jobs:tick`)

One entry point for the host's scheduler (every 5 minutes is a good default), from the same
image as the app. It reads the web app's variables (`DATABASE_URL`, `ENCRYPTION_*`,
`BLIND_INDEX_KEY`, `SMTP_URL`, `MAIL_FROM`, `APP_URL`) and chains expirations, reminders (the
day before, from 09:00 in the site's time zone), the email outbox, the next free slot of result
cards, the purge of patient data and of claim documents 30 days after their decision (needs the
S3 variables). Each sub-job holds a Postgres advisory lock, so overlapping
runs are harmless; `bun run jobs:tick outbox` (or `expire`, `reminders`, `next-free`, `purge`)
(or `claim-documents`) runs one of them. It refuses to run when the overlap constraint is missing.

## Platform administrators

Administrators review claims (`/pro/admin/revendications`), error reports and
removal requests (`/pro/admin/signalements`). There is no sign-up for them:
an existing account with a second factor is promoted in the database, e.g.
`UPDATE directory."user" SET is_platform_admin = true WHERE email = '…';`.
The flag is read on every request; administrators never reach patient data,
and every document or message they decrypt is written to
`directory.platform_audit_events`.

## Open data import (`packages/etl`)

| Variable                                                                                         | Role                                                                           |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `DATABASE_URL_ETL`                                                                               | Connection of the `apercura_etl` role (falls back to `DATABASE_URL`).          |
| `ETL_PROFESSIONS`                                                                                | Profession codes to import (default `10,40,50`).                               |
| `ETL_WORK_DIR`                                                                                   | Temporary directory for downloads (about 1.2 GB).                              |
| `ETL_SOURCE_DIR`                                                                                 | Read the source files from a directory instead of downloading them (fixtures). |
| `ETL_ANS_URLS`, `ETL_AMELI_URL`, `ETL_FINESS_DATASET_URL`, `ETL_GEO_API_URL`, `ETL_GEOCODER_URL` | Override the source URLs (see `docs/data-import.md`).                          |
| `APP_URL`, `REVALIDATE_SECRET`                                                                   | Where and how the import sends its cache tags after a run.                     |

## Tests and tooling

| Variable                | Role                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `SKIP_ENV_VALIDATION`   | `1` skips the start-up validation of the web app's variables.                                                        |
| `DATABASE_URL_TEST`     | Migrated database of the web integration tests: access control, claims, objections and booking (skipped when unset). |
| `ETL_TEST_DATABASE_URL` | Throwaway database of the import integration test (destructive; skipped when unset).                                 |
| `E2E_PORT`              | Port of the Playwright production server (default 3100; development on the next one).                                |
| `MAILPIT_URL`           | Mailpit API read by the sign-up and claim end-to-end tests.                                                          |
| `PSC_MOCK_PORT`         | Port of the mock Pro Santé Connect provider (`apps/web/e2e/mock-psc.ts`).                                            |
| `CI`                    | Set by CI: retries, no server reuse, GitHub reporter.                                                                |
